**[EN] Intro**

Design work used to travel as files. One person exported a screen, sent it away, waited for comments, and hoped everyone was looking at the latest version. Figma changed the basic unit. The design lives in one shared place, reached by a link. Then it adds something more human: you can see the other people inside it. Their names move across the canvas with their cursors, and the file starts to feel less like an attachment and more like a room.

**[MY] Intro**

အရင်က design အလုပ်က file တွေအနေနဲ့ ခရီးသွားတယ်။ လူ တစ်ယောက်က screen တစ်ခု export လုပ်တယ်။ ပို့လိုက်တယ်။ Comment စောင့်တယ်။ ပြီးရင် လူတိုင်း နောက်ဆုံး version ကို ကြည့်နေပါစေလို့ မျှော်လင့်တယ်။ Figma က အခြေခံ ယူနစ်ကို ပြောင်းပစ်တယ်။ Design က link တစ်ခုနဲ့ ရောက်နိုင်တဲ့ မျှဝေထားတဲ့ နေရာ တစ်ခုမှာ နေတယ်။ ပြီးရင် ပို လူသားဆန်တဲ့ အရာ တစ်ခု ထပ်ထည့်တယ်။ အထဲမှာ ရှိတဲ့ တခြား လူတွေကို မြင်နိုင်တယ်။ သူတို့ နာမည်တွေက cursor တွေနဲ့အတူ canvas ပေါ်မှာ ရွေ့တယ်။ File က attachment တစ်ခုလို မခံစားရတော့ဘူး။ အခန်း တစ်ခုလို စပြီး ခံစားရတယ်။

**[EN] 1. The link replaces the file chase**

A Figma file can be shared as one living source. Designers, product managers and engineers open the same canvas instead of passing around copies with names like “final”, “final 2” and “really final”. The latest work is not a question someone has to ask in chat. It is the thing the link opens.

**Principle Card — One Living Source**
Rules applied: Single Source of Truth · Recognition Over Recall
People work better when they can see the current state directly. Removing version detective work frees attention for the design itself.

**[MY] 1. Link က file လိုက်ရှာရတဲ့ အလုပ်ကို အစားထိုးတယ်**

Figma file ကို အသက်ရှင်နေတဲ့ source တစ်ခုအနေနဲ့ မျှဝေလို့ ရတယ်။ Designer၊ product manager နဲ့ engineer တွေက “final”၊ “final 2” နဲ့ “really final” ဆိုတဲ့ copy တွေ လက်ဆင့်ကမ်း မနေဘူး။ Canvas တစ်ခုတည်းကို ဖွင့်တယ်။ နောက်ဆုံး အလုပ်က chat ထဲမှာ မေးရမယ့် မေးခွန်း မဟုတ်တော့ဘူး။ Link က ဖွင့်ပေးတဲ့ အရာကိုက နောက်ဆုံး အလုပ်ပဲ။

**Principle Card — One Living Source**
Applied လုပ်တဲ့ rules: Single Source of Truth · Recognition Over Recall
လူက လက်ရှိ အခြေအနေကို တိုက်ရိုက် မြင်ရရင် ပို ကောင်းကောင်း အလုပ်လုပ်နိုင်တယ်။ Version စုံစမ်းရတဲ့ အလုပ်ကို ဖယ်လိုက်ရင် attention က design ကိုယ်တိုင်ဆီ ပို ရတယ်။

**[EN] 2. A named cursor tells you where attention is**

In multiplayer, a cursor is not anonymous. It carries a colour and a name. You can see who is looking at the header, who is moving toward the form, and who has selected the same component as you. Presence becomes a quiet form of communication before anyone writes a word.

**Principle Card — Presence You Can Read**
Rules applied: Visibility of System Status · Feedback
Visible presence reduces guesswork. A named cursor shows intention, location and activity at a glance, so collaborators can coordinate without interrupting each other for basic context.

**[MY] 2. နာမည် ပါတဲ့ cursor က attention ဘယ်မှာ ရှိလဲ ပြောပြတယ်**

Multiplayer မှာ cursor က နာမည် မဲ့ မဟုတ်ဘူး။ အရောင် တစ်ခုနဲ့ နာမည် တစ်ခု ပါတယ်။ ဘယ်သူက header ကို ကြည့်နေလဲ မြင်နိုင်တယ်။ ဘယ်သူက form ဆီ ရွေ့နေလဲ မြင်နိုင်တယ်။ ဘယ်သူက မင်းနဲ့ တူတဲ့ component ကို select လုပ်ထားလဲ မြင်နိုင်တယ်။ ဘယ်သူမှ စကားလုံး တစ်လုံး မရေးခင်မှာပဲ ရှိနေတာကိုက တိတ်ဆိတ်တဲ့ ဆက်သွယ်မှု တစ်မျိုး ဖြစ်လာတယ်။

**Principle Card — Presence You Can Read**
Applied လုပ်တဲ့ rules: Visibility of System Status · Feedback
ရှိနေတာကို မြင်ရရင် ခန့်မှန်းရတာ နည်းသွားတယ်။ နာမည် ပါတဲ့ cursor က ရည်ရွယ်ချက်၊ နေရာနဲ့ လုပ်ရပ်ကို တစ်ချက်ကြည့်တာနဲ့ ပြတယ်။ ဒါကြောင့် အတူ လုပ်တဲ့ လူတွေက အခြေခံ context အတွက် တစ်ယောက်ကို တစ်ယောက် မနှောင့်ယှက်ဘဲ ညှိလို့ ရတယ်။

**[EN] 3. Observation mode turns a review into a guided look**

When one person presents, others can follow their view of the canvas. The explanation and the picture move together. Nobody has to ask, “Which frame are you on?” or search a huge file for the screen being discussed. The presenter leads the eyes, not just the conversation.

**Principle Card — Shared Attention**
Rules applied: Observation Mode · Progressive Disclosure
People understand more when new information arrives in the order a guide intends. Following one view reduces wandering and lets details appear at the moment they matter.

**[MY] 3. Observation mode က review ကို လမ်းပြပြီး ကြည့်တာအဖြစ် ပြောင်းတယ်**

လူ တစ်ယောက် present လုပ်နေရင် တခြား လူတွေက သူ မြင်နေတဲ့ canvas view နောက်ကို လိုက်လို့ ရတယ်။ ရှင်းပြတာနဲ့ ပုံက အတူတူ ရွေ့တယ်။ ဘယ်သူမှ “မင်း ဘယ် frame မှာ ရှိလဲ” လို့ မေးစရာ မလိုဘူး။ ပြောနေတဲ့ screen ကို file အကြီးကြီးထဲမှာ လိုက်ရှာစရာလည်း မလိုဘူး။ Presenter က စကားဝိုင်းကိုပဲ မဟုတ်၊ မျက်လုံးတွေကိုပါ ဦးဆောင်တယ်။

**Principle Card — Shared Attention**
Applied လုပ်တဲ့ rules: Observation Mode · Progressive Disclosure
သတင်း အသစ်တွေက လမ်းပြသူ ရည်ရွယ်တဲ့ အစီအစဉ်အတိုင်း ရောက်လာရင် လူက ပို နားလည်တယ်။ View တစ်ခုတည်းနောက် လိုက်တာက လမ်းလွဲတာကို လျှော့တယ်။ အသေးစိတ်တွေကိုလည်း အရေးကြီးတဲ့ အချိန်မှာပဲ ပေါ်လာစေတယ်။

**[EN] 4. Comments stay with the thing they are about**

A comment in Figma can sit on the canvas, close to the frame or element it discusses. “Make this smaller” becomes clearer when “this” is visible beside the words. Replies gather around the same point, and resolving the comment can mark the conversation as handled without deleting the design context around it.

**Principle Card — Feedback in Place**
Rules applied: Contextual Feedback · External Memory
People interpret short feedback through location. Keeping the comment with the work preserves the example, the discussion and the decision in one place.

**[MY] 4. Comment က သူပြောနေတဲ့ အရာနဲ့ အတူ နေတယ်**

Figma မှာ comment တစ်ခုက canvas ပေါ်မှာ ထိုင်လို့ ရတယ်။ သူ ပြောနေတဲ့ frame နဲ့ element နားမှာ နေလို့ ရတယ်။ “ဒါကို သေးသေးလုပ်” ဆိုတဲ့ စကားက “ဒါ” ဆိုတာကို စကားလုံးတွေ ဘေးမှာ မြင်ရရင် ပို ရှင်းတယ်။ Reply တွေက အဲဒီ နေရာ ပတ်လည်မှာပဲ စုတယ်။ Comment ကို resolve လုပ်တာက design context ကို မဖျက်ဘဲ စကားဝိုင်း ပြီးသွားပြီ ဆိုတာကို မှတ်ပေးနိုင်တယ်။

**Principle Card — Feedback in Place**
Applied လုပ်တဲ့ rules: Contextual Feedback · External Memory
လူက feedback အတိုကို နေရာကို ကြည့်ပြီး နားလည်တယ်။ Comment ကို အလုပ်နဲ့ အတူ ထားတာက ဥပမာ၊ ဆွေးနွေးချက်နဲ့ ဆုံးဖြတ်ချက်ကို နေရာ တစ်ခုတည်းမှာ ထိန်းထားတယ်။

**[EN] 5. Dev Mode and history make the same room safer**

Figma's multiplayer does not remove the need for handoff. Dev Mode gives engineers a focused way to inspect the design inside the same source. Version history gives the team a way back when a change goes wrong or an older direction needs comparison. The link can stay current because the past is not lost.

**Principle Card — Current, but Recoverable**
Rules applied: Continuity · Error Recovery · Feedback
People take bolder actions when mistakes are visible and reversible. A shared present works better when the team also shares a reliable past.

**[MY] 5. Dev Mode နဲ့ history က အခန်း တူတူကို ပို စိတ်ချရအောင် လုပ်တယ်**

Figma multiplayer က handoff လိုအပ်ချက်ကို ဖယ်ပစ်တာ မဟုတ်ဘူး။ Dev Mode က engineer တွေကို source တူတူထဲမှာပဲ design ကို အာရုံစိုက်ပြီး စစ်ဖို့ နည်းလမ်း တစ်ခု ပေးတယ်။ Version history က အပြောင်းအလဲ တစ်ခု မှားသွားရင် team ကို ပြန်သွားလို့ ရတဲ့ လမ်း ပေးတယ်။ Direction အဟောင်း တစ်ခုကို နှိုင်းယှဉ်ဖို့ လိုရင်လည်း သုံးလို့ ရတယ်။ Link က လက်ရှိ အခြေအနေမှာ နေလို့ ရတယ်။ အတိတ်ကို မပျောက်သွားလို့ပဲ။

**Principle Card — Current, but Recoverable**
Applied လုပ်တဲ့ rules: Continuity · Error Recovery · Feedback
အမှားတွေကို မြင်နိုင်ပြီး ပြန်ပြင်နိုင်ရင် လူက ပို ရဲရဲ လုပ်တယ်။ Team က စိတ်ချရတဲ့ အတိတ်ကိုပါ အတူ မျှဝေထားရင် မျှဝေထားတဲ့ ပစ္စုပ္ပန်က ပို ကောင်းကောင်း အလုပ်လုပ်တယ်။

**[EN] The honest summary**

Figma's breakthrough was not simply putting design in a browser. It made collaboration visible inside the work. A link removes the copy problem. Named cursors remove the “where are you?” problem. Observation mode and canvas comments keep people looking at the same thing while they talk about it. Multiplayer has a cost, though. A busy canvas can feel crowded. Live presence can feel like being watched. Too many comments can become another inbox, and a shared file still needs permissions and team habits to stay tidy. Figma gives the team one room. The team still has to behave well inside it.

**[MY] အမှန်အတိုင်း အကျဉ်းချုပ်**

Figma ရဲ့ အောင်မြင်မှုက design ကို browser ထဲ ထည့်ရုံပဲ မဟုတ်ဘူး။ အလုပ်ထဲမှာပဲ အတူ လုပ်တာကို မြင်သာအောင် လုပ်ခဲ့တယ်။ Link က copy ပြဿနာကို ဖယ်တယ်။ နာမည် ပါတဲ့ cursor က “မင်း ဘယ်မှာ ရှိလဲ” ဆိုတဲ့ ပြဿနာကို ဖယ်တယ်။ Observation mode နဲ့ canvas comment က လူတွေကို စကားပြောနေစဉ်မှာ အရာတူတူကို ကြည့်နေစေတယ်။ ဒါပေမဲ့ multiplayer မှာလည်း ပေးရတဲ့ တန်ဖိုး ရှိတယ်။ အလုပ်များတဲ့ canvas က လူ ပြည့်ကျပ်သလို ခံစားရနိုင်တယ်။ Live presence က စောင့်ကြည့်ခံနေရသလို ခံစားရနိုင်တယ်။ Comment တွေ များလွန်းရင် နောက် inbox တစ်ခု ဖြစ်လာနိုင်တယ်။ Shared file က သပ်ရပ်နေဖို့ permission နဲ့ team အကျင့်တွေ လိုသေးတယ်။ Figma က team ကို အခန်း တစ်ခု ပေးတယ်။ အဲဒီ အခန်းထဲမှာ ကောင်းကောင်း ပြုမူရမှာက team ရဲ့ အလုပ်ပဲ။
